# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

TinkerSignals is a visual, TinkerCad-style lab for learning audio coding and compression. Users wire blocks (sources → quantizers/encoders → channel/network → decoders → output) on a React Flow canvas; real audio runs through them. All UI text, comments, docs and commit messages are in **Spanish** — keep it that way.

## Commands

```bash
npm run dev          # Vite dev server on http://localhost:5173 (.claude/launch.json "dev" uses --strictPort)
npm test             # Vitest, Node environment, all src/**/*.test.ts
npx vitest run src/blocks/codecs.test.ts        # single file
npx vitest run -t "DPCM"                        # tests whose name matches
npm run typecheck    # tsc --noEmit
npm run lint         # eslint .
npm run build        # typecheck + vite build
npm run bench        # CELP benchmark (BENCH=1, skipped in normal test runs)
```

Prettier config is in `.prettierrc`. `public/sounds/*.wav` are generated by `node scripts/make-sound-clips.mjs <dir-with-mp3s>`; credits in `public/sounds/CREDITS.md`.

## Architecture

Dependency direction is one-way: `ui → runtime → engine ← blocks`. ESLint (`no-restricted-imports`) forbids `src/engine/**` and `src/blocks/**` from importing React, React Flow or `ui/`, so the engine and every block are pure TS testable in Node without a browser.

- **`src/engine/types.ts` is the contract.** Cable values are a tagged union `PortValue = Signal | Bitstream | PacketStream | Frames | Image` (`kind` is the port type). Adding a new cable type means extending this union, `ValueSummary` + `engine/summary.ts`, `runtime/probe.ts`, `ui/theme.ts` (`portColor`), the cable/handle CSS, `CableEdge` label, `ProbePanel` and the node thumbnail in `BlockNode`.
- **Images** (`kind: 'image'`) carry one `ImagePlane` per channel, each with its own size (that is how 4:2:0 chroma travels); pixels are 0–255, `domain: 'dct'` planes hold block coefficients padded to the block size with the real size in `crop`. Shared image maths lives in `engine/dsp/image.ts`. Non-audio bitstreams set `sampleRate: 0` and `header.unit = { name, count }`, and the UI then shows bits per unit (looked up through nested `header.inner` too).
- **Block rule from the user:** creating or changing a block must not require touching the engine/UI core; if a block needs something new, add it once as a generic, data-driven capability (a new param type, plot kind or cable type) — never a per-block special case.
- **`engine/evaluator.ts`** runs the graph in topological order (`graph.ts` validates types and cycles) with a per-node cache keyed on params + upstream results, so moving a slider only recomputes that node and its descendants. Errors are isolated per node; throwing `BlockWaiting` (from `engine/errors.ts`) marks a node "waiting" instead of red.
- **Latency is reported, not applied.** Each block returns `latencyMs`; the evaluator accumulates it along paths and the Output compares against G.114's 150 ms. Signals stay time-aligned so comparators can diff them.
- **Bitstreams carry real packed bits.** Encoders write with `BitWriter` into `Bitstream.bytes`; decoders read them back. Only what goes in `header` is out-of-band (never corrupted by channel blocks); everything in the bytes counts toward bitrate and can be damaged. `referenceBits` (16-bit PCM equivalent) travels through the whole chain so compression ratio is always relative to the original. Decoders call `expectCodec` to fail clearly on mismatched wiring. Lossless coders (Huffman, arithmetic, LZW, RLE) take a `bitstream` in and nest the previous header in `header.inner`.
- **`src/runtime/`**: the engine lives in a Web Worker (`worker.ts`, exposed via Comlink; `client.ts` is the main-thread proxy). Audio assets are transferred into the worker with `setAsset`. `probe.ts` computes cable analysis (spectrum, spectrogram) for the cable inspector; `benchConfigs.ts` feeds the rate–quality comparison panel. The worker has two scopes: `main` and `interior`.
- **`src/ui/`**: Zustand store (`store.ts`) + React Flow canvas. `history.ts` = undo/redo; `lib/share.ts` compresses the circuit into a shareable link; `lib/assetDb.ts` persists uploaded/recorded audio in IndexedDB. Lessons (`lessons/lessons.ts`) and ready-made circuits (`examples.ts`) are plain data; `examples.test.ts` checks they are valid graphs.

### Blocks

One block = one folder `src/blocks/<id>/` with `index.ts` (`export default defineBlock({...})`) and `locales/es.json`. Blocks are auto-discovered via `import.meta.glob` in `src/blocks/index.ts`; the `id` must equal the folder name, and folders starting with `_` are ignored (`_shared/` = codec cores shared by encoder/decoder pairs, `_template/` = annotated template). Full guide: `docs/como-crear-un-bloque.md`. Key rules:

- `process` must be pure and deterministic — no `Math.random()`, use `seededRandom` from `_shared/random.ts`.
- Encoder/decoder pairs: algorithm in `_shared/<codec>.ts`, two thin blocks with `family` + `familyRole`; the family name goes in `src/i18n/es.json → families`.
- Optional `interior(params, inputs)` returns an equivalent circuit of basic "piezas" (framer, DCT, FFT, Levinson…) shown on double-click; `src/blocks/interiors.test.ts` checks the interior's output matches the real block. Interior inputs use the hidden `inner-signal-in` / `inner-bitstream-in` blocks.
- Optional `inspectAt` produces per-instant plots for the "lupa temporal".
- `registry.test.ts` fails if a block is missing any locale string. Every entry in a block's `concepts` must have a theory card in `src/theory/es.ts` (`theory.test.ts` enforces this); theory cards use KaTeX.
- Gotcha: Vitest's `fsModuleCache` is disabled in `vite.config.ts` because the glob-based discovery doesn't notice new folders otherwise.

`src/blocks/codecs.test.ts` has a `chain` helper (generator → blocks, linear) and `src/blocks/image.test.ts` a `circuit` helper (arbitrary nodes + `"a.out>b.in"` wires) — the quickest way to test a new codec end to end. Param types: `number`, `select`, `boolean`, `text`, `audio`, `image`, `external`; plot kinds: `line`, `bars`, `image`, `text`.

## Repo-local tooling

`video/` is a separate npm project (Playwright + Remotion) that records the real app and renders the promo video in `docs/video/`; it has its own `package.json` and is excluded from the root ESLint, tsconfig and Vitest. See `video/README.md`.

`.agents/skills/` (symlinked from `.claude/skills/`) contains the `design-taste-frontend` and `frontend-design` skills used for UI design reviews. They are third-party and local only: `.agents/`, `.claude/skills/`, `skills-lock.json` and their scratch output `.taste-skill/` are gitignored, so a fresh clone does not have them.
